# MISSION.md Format

`MISSION.md` lives at the teaching workspace root. It captures why the user is learning this topic and should steer lesson choice, source selection, exercises, and scope.

## Template

```md
# Mission: {Topic}

## Why

{1-3 sentences describing the concrete real-world outcome. Avoid abstract goals like "understand X"; push for what changes in work or life when the user can do this.}

## Success looks like

- {Specific observable capability}
- {Specific observable capability}

## Constraints

- {Time, budget, prior commitments, learning preferences, or other bounds}

## Out of scope

- {Adjacent topics the user does not want to chase right now}
```

## Rules

- Keep one mission per workspace.
- Prefer concrete outcomes over abstract curiosity.
- Push back on vague missions before writing lessons.
- Revise the mission when reality shifts, and record the change in a learning record.
- Keep the file short enough to work as a compass rather than a plan.
