# Doc Shapes

## Default Page

```md
# <Title>

> <One-line summary.>

## TL;DR

- What this is:
- Who should care:
- What to do first:

## Quick path

1. Do this.
2. Verify this.
3. Stop here unless you need details.

## Common tasks

| Task | Where |
|---|---|

## Facts / contract

Tables, commands, config, APIs, ownership, guarantees.

## Examples

Small examples before large examples.

## Details

Design, trade-offs, edge cases, rationale.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|

## Reference / appendix

Long lists, links, historical notes, full matrices.
```

## README

Use README as the entry point.

Order: summary, quick start, common commands, configuration, usage, validation, architecture link, related docs.

## Runbook

Order: when to use, prerequisites, procedure, validation, rollback/recovery, escalation.

## Reference

Use tables. Avoid narrative. Include source paths/links when facts can drift.

## Configuration

| Key | Required | Default/example | Source | Purpose |
|---|---|---|---|---|

Never include real secret values.
